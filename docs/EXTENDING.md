# Как развивать модель и код

Сначала прочитайте [руководство пользователя](../USER_GUIDE.md). Здесь описаны
точки расширения для тех, кто хочет менять уравнения, правила и анализ.
Комментарии в Python оставлены на английском в едином стиле с исходниками.

## Рабочая копия

Установите проект в режиме разработки:

```bash
python -m pip install -e '.[test]'
python -m unittest discover -s tests -q
```

Теперь изменения исходников подхватываются при следующем запуске Python.
Перезапустите интерпретатор/ноутбук после редактирования импортированного модуля.
Работайте с новым именем run и сохраняйте исходную рабочую версию, чтобы можно
было воспроизвести старые результаты. JSON меняет числа; Python меняет формулы.

## Карта кода

| Задача | Где менять |
|---|---|
| Параметры отдельного опыта | Копия конфига, экспортированная командой examples |
| Реакции T/P, функционал и подвижность | `engine/model/cultural_v01.py` или новый модельный модуль |
| Время рождения и вероятность выбора T | `engine/model/event_rules.py` |
| Начальное пространственное поле newborn P | `engine/model/birth_profiles.py` |
| Форма геометрической маски | `engine/model/masks.py` |
| Наследование/мутации параметров | `engine/events/p_birth.py` |
| Lineage metadata и семантика целей | `engine/events/provenance.py`, `targeting.py` |
| Аналитический эталон | `engine/analysis/reference_solutions.py` |
| Численные метрики | `engine/analysis/error_metrics.py` |
| Отрисовка | `engine/visualization/` |
| CLI | `engine/cli/` |
| Контракт архивов | `engine/archive.py` и `docs/ARCHIVE_CONTRACT.md` |

Численный маршрут: коэффициенты → восстановление полей на сетке → вычисление
RHS → проекция → производные коэффициентов. Внутри сегмента набор полей фиксирован.
Событие завершает сегмент, изменяет физическое состояние и создаёт следующий.
Обычно для новой реакции или hazard этот маршрут менять не нужно.

## Договорённости о массивах

- `U.shape == (len(fields), *grid.shape)`; `fields[i]` описывает именно U[i].
- При работе provider используются текущие поля; глобальный registry также хранит
  неактивные исторические записи. Не переносите индексы между этими списками.
- `grid.mesh` содержит физические координаты ячеек, `grid.volume` — объём одной ячейки.
- Интеграл скалярного поля: `float(values.sum() * grid.volume)`.
- Реакция возвращает массив формы U. Закон для отдельного поля возвращает grid.shape.
- Не считайте, что T всегда имеет индекс 0. Используйте family/model_type/stable ID.
- Не изменяйте U и registry внутри RHS, rate или reference callbacks.

`a` в GalerkinProvider — вектор коэффициентов, не сеточное поле. Пары field ID/mode
задают порядок его колонок. Нельзя добавлять компоненту a посреди шага интегратора.

## Своя реакция или модель

Чтобы сохранить доступ к исходной модели старых run, скопируйте
`engine/model/cultural_v01.py` в `engine/model/my_model.py`. В копии добавьте
функцию перед `REACTION_LAWS`:

```python
def damped_progress(i, U, fields, grid, t, total):
    p = fields[i]["parameters"]
    extra_decay = float(p.get("extra_decay", 0.0))
    return progressive_v1(i, U, fields, grid, t, total) - extra_decay * U[i]
```

Добавьте в словарь `REACTION_LAWS` пару `"damped_progress": damped_progress`.
В конфиге поставьте `"model": "my_model"`, а у нужного начального поля либо в
`stochastic_events.p_birth` — `"model_type": "damped_progress"`.
Для начального поля extra_decay задаётся в parameters. Для newborn учтите его
parameter_policy: новое значение должно попадать в создаваемые parameters,
например через parameter_ranges при random/inherit_mutate, а не как неизвестный
верхнеуровневый ключ конфига.

Имя файла должно быть простым идентификатором; модуль обязан предоставлять
`build_model(parameters=None)`, возвращающий Model. Копирование существующей
модели сохраняет этот интерфейс. Family T/P используется для событий и группировки;
model_type выбирает локальную реакцию. Новая reaction-функция должна поддерживать
все нужные размерности и возвращать конечные значения.

Для более глубокой замены Model собирается из functional, mobility и reaction.
`functional.chemical_potential` возвращает массив формы U. Mobility — матрица
связей полей с допустимым пространственным broadcasting; смотрите существующие
реализации и `grid.transport`. Если сохраняете birth с новыми полями, подвижность
должна поддерживать используемый birth-matrix интерфейс. Копирование совместимого
CulturalMobility безопаснее, чем замена произвольной функцией без этого интерфейса.
Не называйте новый функционал энергетическим доказательством без отдельной проверки.

## Свой per-T hazard

Добавьте в `engine/model/event_rules.py`:

```python
@register_source_rate("mass_squared")
def mass_squared(source_index, U, fields, grid, t, params):
    mass = float(np.maximum(U[source_index], 0.0).sum() * grid.volume)
    return float(params.get("beta", 1.0)) * mass * mass
```

В существующем блоке p_birth задайте `source_mode: "per_T"`,
`source_rate_function: "mass_squared"`, `rate_parameters: {"beta": 0.2}`.
Остальные параметры рождения оставьте из рабочего конфига. Это пример другой
модельной гипотезы, не замена стандартной формулы по умолчанию.

Результат — конечная неотрицательная **частота**, а не вероятность. Её сумма по
активным T интегрируется clock; нормировка для выбора источника выполняется отдельно.
Адаптивный интегратор многократно вызывает правило на пробных состояниях. Поэтому
не вызывайте здесь RNG, не увеличивайте счётчики, не записывайте события и не меняйте U.
Случайные решения событий используют `sim.rng` в event-map слое.

## Свой профиль newborn P

Добавьте в `engine/model/birth_profiles.py`:

```python
@register_birth_profile("quadratic_inside_T")
def quadratic_inside_T(U, fields, grid, t, params):
    return inside_T(U, fields, grid, t, {**params, "power": 2.0, "fallback": "fail"})
```

Выберите `birth_profile: "quadratic_inside_T"`; amplitude и epsilon остаются в
birth_profile_parameters. Пример намеренно фиксирует power=2 и fail policy.
Базовая inside_T уже проверяет амплитуду, epsilon и возвращает эффективные параметры.

Интерфейс профиля: `(U, fields, grid, t, params)` →
`(values, effective_parameters, fallback_used)`. values должен быть неотрицательным,
конечным и совместимым с grid.shape. effective_parameters и fallback — JSON-совместимая
скалярная/config metadata, не пространственные массивы.

В per_T режиме сюда поступает только выбранный T! Не ищите остальные поля по
предположительным индексам. Accessibility применяет общий wrapper; не умножайте
на неё повторно. Проекцию выполняет следующий сегмент. Пользовательский профиль
сам отвечает за свою zero-source policy: специальная защита стандартного inside_T
не должна предполагаться для произвольного имени; пример выше явно задаёт fail.

## Маски и аналитические эталоны

Для геометрии используйте `@register_mask("name")` в masks.py. Функция принимает
координаты `(*grid.mesh, t=..., params=...)`; возвращает значение в [0,1],
совместимое с grid.shape. Пример my_catastrophe уже работает в 1D/2D/3D.
Событийная маска фиксируется в начале события, даже если функция принимает t.

Для нового эталона используйте `@register_reference("name")` в
reference_solutions.py. Функция `(grid, t, params)` возвращает реальные значения
на указанной сетке. Выбирайте её через `analyze --reference name` и отдельный JSON
reference-params. Совпадение начальных и граничных условий с численной задачей
нужно обеспечить явно; analyzer не доказывает, что выбран правильный эталон.

## Что сохранять при доработках

1. Machine ID — идентичность; display_label — подпись. Не используйте подписи как ключи.
2. source_T и inheritance_parent — разные связи. Старый source не меняется после T split.
3. Внутри сегмента размерность и порядок коэффициентов фиксированы.
4. Hazard, spatial profile и continuous dynamics выполняют разные роли.
5. Архивы читаются без pickle; поля schema и формы массивов описаны в контракте.
6. Изменение визуализации не должно запускать расчёт заново.

Файл модели хешируется целиком. Изменение его комментариев также меняет хеш.
В v0.9.2 комментарии добавлены также к функциям cultural_v01.py: его формулы
не изменились, но побайтовый хеш отличается. Просмотр старых кадров продолжает
работать. Для Newton/RHS-анализа старых run используйте записанный исходник из
model_source в отдельной копии проекта. Не отключайте проверку хеша ради удобства.

## Проверка и передача изменений

Для изменения формулы сначала проверьте маленькую задачу, затем новую ветку
поведения отдельным тестом и весь набор:

```bash
python -m unittest discover -s tests -p 'test_provenance.py' -q
python -m unittest discover -s tests -q
```

После изменения PDE дополнительно сравните с аналитическим/независимым эталоном
и проверьте сходимость. После изменения упаковки проверьте установку wheel вне
каталога исходников. При передаче патча опишите формулу/поведение, конфиг, seed,
проверки и изменения совместимости. Добавьте новую команду в таблицу README,
новый пример — в package data; пользователь должен повторить результат без
редактирования внутренних путей.


## Чтение исходников и выбор времени

[FUNCTION_REFERENCE.md](FUNCTION_REFERENCE.md) перечисляет все 220 функций
рабочего пакета с сигнатурами и пояснениями. У каждой функции есть существующий
docstring либо добавленный непосредственно перед определением комментарий.
Исторические test fixtures не переписываются: они остаются эталонами совместимости.

Для доработки выбора времени начните с `ArchiveSequence.select_time` в
`engine/visualization/spectral.py`: метод работает по временам сохранённых кадров,
не реконструируя все поля. `frame` восстанавливает только выбранный кадр,
`plot_spectral` рисует его и возвращает selection metadata. CLI `plot.main`
проверяет совместимость флагов и печатает фактическое время.

В Python используется `plot_spectral(path, time=12.5, save="frame.png")`;
в CLI — `--time 12.5`. Новые аргументы добавлены в конец сигнатуры, поэтому
прежние позиционные вызовы сохраняются. Для статичного кадра возвращается dict
с frame_index, requested_time, actual_time, segment, time_mode, event_side;
для анимации — None. `requested_time` равен None при выборе через frame_index.
Структура NPZ/manifest и ODE pipeline не менялись.
